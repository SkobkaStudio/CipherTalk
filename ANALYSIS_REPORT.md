# Отчет анализа CipherTalk (Stage 0)

## Кратко
Текущий код базово работает, но местами есть косяки/заглушки. Ниже — что нашел.

## app.js (клиент) / сервер
- Клиентское E2EE уже есть (ECDH P-256 + AES-GCM в браузере), но логика обмена ключами не совсем чистая. Ключи хранятся в localStorage (`ciphertalk_keys`) — ок. При отправке используется общий ключ чата, получаемый через `getChatKey` (деривация по публичному ключу собеседника/члена). Нужно переписать шифрование под требование "сервер хранит только {ciphertext, iv}" и уникальный IV для каждого сообщения — на клиенте уже генерируется 12-байтный IV, ок. Но лучше сделать чистую реализацию с нуля по шагам.
- Поиск пользователей: на клиенте вызывается GET `/api/search-users?query=...`, на сервере есть в profileController.searchUsers — ищет по name/phone/username без учета регистра (нижний регистр) и исключает себя. Требование: "GET /api/users/search?q=... (поиск по username, email, phone без учета регистра)". В API сейчас используется `query` параметр, не `q`. Также нет поиска по email (у User нет поля email). Нужно добавить поддержку `q` и при желании поле email, а также endpoint `/api/users/search`. Клиент нужно поправить на fetch.
- Отправка сообщений: работает через WS `send_message` с `{content, iv, msgType}`. Сервер шифрует содержимое при сохранении через `encryptionService.encryptMessage` (at-rest) и расшифровывает при отдаче. Но по требованию Stage 1 — "сервер хранит только {ciphertext, iv}". Сейчас в БД у сообщения хранится `encrypted_content` (зашифрованное at-rest сервером) и `iv`. То есть сервер хранит зашифрованное им содержимое. Но по заданию говорится про клиентское E2EE: "ECDH (P-256): Приватный ключ только в браузере, публичный на сервере. AES-256-GCM: Уникальный IV для каждого сообщения. Сервер хранит только {ciphertext, iv}". То есть сообщение, которое клиент шифрует своим E2EE ключом — клиент присылает уже зашифрованное `{ciphertext, iv}` (или в нужном формате). Сервер должен просто хранить эти поля как есть, без своего дополнительного шифрования at-rest поверх клиентского E2EE. Нужно переделать.
- WebSocket: есть дубли подключений (MAX_SOCKETS_PER_USER), heartbeat/ping, но требуется "Без дублей, синхронизация вкладок, авто-реконнект". На клиенте reconnection логики не нашел явно — нужно добавить.
- Много функционала уже есть частично (реакции, reply/forward/edit/delete/pin, голосовые/видео-кружки, файлы) — нужно довести до рабочего состояния, убрать заглушки если есть.

## Проблемные места
- `searchUsers` в контроллере ищет по name/phone/username; нет поддержки параметра `q`, нет поля email. Нужно привести к требованию.
- На сервере при сохранении сообщения делается `encryptionService.encryptMessage(content)` — двойное шифрование/не то. Нужно изменить на хранение клиентского шифротекста как есть.
- Маршруты: нужно добавить `/api/users/search` (совместимо с `/api/search-users`).
- Клиентский код большой, есть места где можно улучшить. Но не будем патчить старый код если сильно сломан — будем переписывать нужные модули.
